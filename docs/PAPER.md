# Remember at the Right Game: Event-Triggered Memory for Game Companions

# 打到那一局就想起：面向游戏陪伴的事件触发记忆

**GameMemo 项目 · 2026 年 10 月** · 代码：`gamememo/game/` · 数据：`bench/data/e2e_g1.json`、`bench/data/e2e_g2.json` · 实验记录：`docs/EXPERIMENTS.md`（E11–E21）

---

## 摘要 / Abstract

**English.** Long-term memory for LLM agents (Mem0, MemGPT, retrieval over chat history) is built for one interaction pattern: the user asks, the memory retrieves. A game companion works differently. Besides the chat, it sees a second, objective stream — every match the player plays — and the moments that matter most are ones where nobody asks anything: the next game on a hero the player swore off, the game that reaches the tier they promised themselves a reward for, the third loss of an evening after they asked to be told to log off. We present **GameMemory**, a memory design built on three properties of game data. (1) *Match data is the system of record*: game-state questions are answered by computation over a match ledger, and the player's own claims are checked against it. (2) *Chat is grounded in the match it follows*: an exchange is aligned to the match timeline when written, so deictic talk ("this hero", "next time we duo he…") resolves to concrete game entities. (3) *Intentions become game cues that the match stream fires*: vows, goals, rules and agreements are indexed by a hero, a tier on the rank ladder, a count of losses in one evening, or a friend queued with, and are recalled on the first matching game after they were said. On two sealed, pre-registered benchmarks with simulated match histories and chats written by code-blind authors, GameMemory answers game-state questions at 0.944 versus 0.236–0.306 for generic memory given the same match data (E20), and brings up the right intention at the right game moment with a score of 0.861 versus 0.339 (Mem0), 0.504 (retrieval) and 0.583 (full chat history), whose recall is 0.000–0.063 (E21). Without any LLM, the intention index alone fires on 47 of 48 cue games and on none of 67 negatives.

**中文.** 现有的长期记忆（Mem0、MemGPT、对聊天记录做检索）都假设一种交互：用户提问，记忆检索。游戏陪伴不一样：除了聊天，它还能看到另一条客观的数据流，也就是玩家打的每一局；而最需要记忆的时刻往往没有人提问——玩家发誓不再用的英雄又被选上的那一局、定了奖励的那个段位终于升上的那一局、说过"连输三把就让我下线"之后的第三次连输。我们提出 **GameMemory**，基于游戏数据的三个特点设计：(1) **对局数据是系统记录**：游戏状态的问题由对局账本计算回答，玩家自己的说法也拿它核对；(2) **聊天钉在它紧跟的那一局上**：写入时把每段对话对齐到对局时间线，"这英雄""下次双排他…"这类指代被解析成具体的英雄、朋友；(3) **意图变成由对局流触发的游戏线索**：发誓、目标、规矩、约定按英雄、段位阶梯上的档位、一晚上的连败把数、一起双排的朋友建立索引，在说完之后第一次对上的那一局被想起。在两个预登记、封存的基准上（模拟对局 + 不看代码的作者编写的聊天），GameMemory 回答游戏状态题 0.944，通用记忆在拿到同样对局数据时只有 0.236–0.306（E20）；在游戏时刻主动提起正确的意图，主分 0.861，Mem0 0.339、检索 0.504、全部聊天 0.583，而这三者的召回只有 0.000–0.063（E21）。不经过任何 LLM，意图索引本身在 48 个线索局里命中 47 个，在 67 个负例上 0 次误触发。

## 1. 引言

### 1.1 通用记忆的隐含假设

LLM 智能体的长期记忆大体有三类做法：改写式记忆在写入时让模型把对话抽成事实（Mem0 [1]、MemGPT [2]）；检索式记忆保存对话片段，提问时检索；长上下文把历史全部放进 prompt。它们共享一个隐含假设——**记忆由查询驱动**：有一句话（提问）作为线索，记忆才会被读出来。公开基准也都是问答形式（LoCoMo [3] 等）。

### 1.2 游戏陪伴的数据有什么不同

| | 通用聊天助手 | 游戏陪伴 |
|---|---|---|
| 信息来源 | 只有聊天 | 聊天（主观、稀疏、会夸大）+ 对局数据（客观、密集、带精确时间） |
| 聊天和事件的关系 | 无 | 聊天紧跟在对局之后，玩家知道助手看到了那局，常用指代（"这英雄""这把""他"） |
| 时间 | 日历 | 赛季、段位进程、"第一次上钻石那天"、"连跪最多那次" |
| 世界的结构 | 开放 | 封闭：段位是有序阶梯，英雄分自己和对面，连败可以精确计数 |
| 最需要记忆的时刻 | 用户提问时 | 往往是一局结束、没人提问的时候 |

最后一行是本文的核心。玩家说过的很多话是**意图**：对未来某个游戏情境的承诺或计划。

> "这英雄我再也不碰了。" · "上星耀就买那根海竿。" · "以后一晚上连输三把就下线，你提醒我。" · "下次跟小周双排先说好分路。"

这些话该被想起的时机是一局游戏，而不是一句提问。心理学把这种记忆叫**基于事件的前瞻记忆**（event-based prospective memory [4]）：记住"当某件事发生时要做某事"，由外部事件而不是主动回想触发。通用记忆系统没有这个入口。

### 1.3 贡献

1. **问题**：提出游戏陪伴记忆的两个任务——游戏状态问答（以系统记录为准）和**游戏时刻的主动回忆**（没有提问，由对局触发）——并说明通用记忆在结构上做不到后者。
2. **方法**：GameMemory，由对局账本、原话日志、游戏本体和**意图索引**组成。意图索引在写入时把聊天对齐到对局时间线、用游戏规则把意图变成线索，在对局流中按"说完后第一次"触发；不调用 LLM，不改写原话。
3. **基准**：两个封存的中文基准 e2e_g1（游戏状态 + 聊天问答）和 e2e_g2（游戏时刻主动回忆，175 个时刻），对局由模拟器生成、答案由对局计算，聊天由不看代码的作者编写；实验在跑 test 之前预登记。
4. **结果与分析**：GameMemory 在两个任务上都显著优于 Mem0、检索和全部历史，换 7B 回复模型后差距更大；我们分解了通用做法的三种失败方式，并用消融说明"决定何时说""只在第一次触发"各自的作用，同时如实报告没有成立的假设和剩余的弱点。

## 2. 任务

**输入**：一位玩家的对局流 $M = (m_1, m_2, \dots)$（每局含时间、模式、英雄、位置、胜负、KDA、段位变化、双排对象）和聊天流 $C$（带时间的玩家—助手对话）。

**任务一：游戏状态问答**（E20）。给定时刻 $t$ 和问题 $q$（"我上赛季最高到哪""我孙尚香胜率多少""我第一次上钻石那天跟你说了啥"），回答。答案由 $M$ 精确计算，或由 $C$ 中的原话给出。

**任务二：游戏时刻的主动回忆**（E21）。在每局 $m_i$ 结束后，助手决定是否主动开口；若开口，要说出聊天里的哪件事和这局有关。设玩家在时刻 $s$ 说出一条意图 $u$，其触发条件是游戏情境 $\kappa(u)$（例如"玩家使用英雄 X"），则 **正例** 是 $s$ 之后第一个满足 $\kappa(u)$ 的对局，助手应开口并说出 $u$ 的内容；**负例** 是不应开口的对局（见 §4.2）。

## 3. 方法：GameMemory

```
对局流 ──► GameLedger（对局账本，系统记录）──► 游戏档案卡、英雄记录、事件日期、每局情境
               │                                   │
               │ 对齐                               │ 触发
               ▼                                   ▼
聊天流 ──► RawMemory（原话 + 时间）──► IntentionIndex（意图 → 游戏线索）──► 这一局该提起的话
                 │
                 └─► 按问题检索原话、助手的承诺
```

### 3.1 对局账本：对局数据是系统记录（`ledger.py`）

账本保存全部对局，按需精确计算：当前段位、各赛季最高段位和场次胜率、每个英雄的场次 / 胜率 / KDA、最近常用英雄、位置分布、最长连败、第一次到达每个档位的日期，以及每一局结束时的情境（这局的英雄和结果、段位变化、当晚战绩、当晚排位连输把数）。这些浓缩成约 450 字的**游戏档案卡**随每次回答带上。游戏属性只来自账本，不从聊天里抽取；玩家声称的段位高于记录时，原话后附注"与系统记录不符：上赛季最高其实是钻石三"。

### 3.2 原话日志（`personal/raw.py`）

生活、情绪、助手的承诺按原话带时间保存，写入不调用 LLM。我们此前的实验表明改写式记忆的主要损失在写入：LoCoMo 上可以在原话中找到的答案有 67% 不在 Mem0 的记忆库里，原话检索比 Mem0 高 0.181 [+0.155, +0.207]（E19，见 `docs/FINDINGS.md`）。

### 3.3 游戏本体（`ontology.py`）

段位阶梯（档位、小段、星数）、赛季起止、五个位置与英雄的对应；从文本识别段位（"打王者"是游戏，不是段位）、英雄、位置；判断一句话在聊游戏还是聊生活。

### 3.4 意图索引：由对局流触发的前瞻记忆（`intentions.py`）

**(a) 写入时对齐对局。** 每段对话找到它紧跟的那一局（同一晚、对话之前的最后一局），记为它的**锚点**。玩家说"这英雄 / 这把"时，指的就是锚点那局的英雄；说"下次双排他…"而没有点名时，指的是当晚一起双排的朋友。

**(b) 只索引意图。** 只有前瞻性的话（发誓、目标、规矩、"提醒我"、约定）进入索引，其余对话不产生线索。

**(c) 用游戏规则把意图变成线索。**

| 线索 | 从哪里来 | 游戏规则排除的情况 |
|---|---|---|
| 英雄 $h$ | 玩家自己用的英雄（点名或由锚点解析） | "对面的后羿"（对手的英雄） |
| 档位 $T$ | "上 / 到 / 冲 / 升 + 档位" | "我现在钻石二"（现状不是目标）；"胖虎说他上星耀就…"（别人的目标） |
| 连败 $n$ | "连输 / 连跪 $n$ 把" | — |
| 双排朋友 $p$ | 点名，或"双排"+ 当晚的双排对象 | — |

**(d) 在对局流中触发，只在第一次。** 一局 $m$ 结束时，意图 $u$（说于 $s$）被触发当且仅当 $m$ 满足其线索（用了英雄 $h$ / 这局升入档位 $T$ / 当晚排位连输恰好 $n$ 把 / 和 $p$ 双排），**并且** $s$ 与 $m$ 之间没有别的对局已经满足过它。对局记录告诉我们玩家在这期间是否已经用过这个英雄。

**(e) 记忆决定何时说，模型只负责怎么说。** 有意图被触发时，GameMemory 把那段原话（附上当时那局和"这是那次之后他第一次再用 X"）交给回复模型，要求它主动提起；没有触发时直接不开口，不调用 LLM。

意图索引不调用 LLM、不改写原话，每次触发都能追溯到一句原话和一局对局。

## 4. 基准

### 4.1 共同的构造原则

- **对局由模拟器生成**（`bench/gamesim.py`）：每位玩家 2026 年 3–9 月约 300–520 局，排位按星数涨落、赛季重置、主玩英雄分阶段更换、熟练度提升、连败后状态下滑；答案由对局精确计算。
- **聊天由不看代码的作者编写**：作者只拿到计划文件（每段聊天的日期、当晚战绩、要埋的内容），不接触被评测的代码。
- **封存与预登记**：test 集在任何系统运行之前提交；假设、上下文、判分在跑 test 之前写进 `docs/EXPERIMENTS.md`；所有比较用按题 / 按时刻配对的 bootstrap 95% 置信区间。
- **回复模型** `qwen2.5:3b`（温度 0），所有上下文共用同一模型。

### 4.2 e2e_g2：游戏时刻的主动回忆

每位玩家约 12 段聊天，其中埋 6 条意图（发誓不玩 1、英雄教训 2、段位目标 1、连输规矩 1、双排约定 1）和 2 条干扰。英雄类意图一半点名、一半只说"这英雄"（由计划指定）。作者为每条意图给出判分关键词。

| 时刻类别 | 应该 | 含义 |
|---|---|---|
| 正例（5 类意图） | 开口并说出该意图 | 意图说出后，线索第一次出现的那局 |
| 对面英雄 | 沉默 | 玩家吐槽过"对面的 X"，之后自己第一次用 X |
| 朋友的目标 | 沉默 | 朋友说"上 T 就…"，玩家自己升入 T |
| 目标前的小段晋升 | 沉默 | 目标档位之前的小段升级 |
| 只连输两把的晚上 | 沉默 | 定了"连输三把"规矩之后 |
| 普通对局 | 沉默 | 从没聊过的英雄 |
| 重复（单独报告） | 沉默 | 同一英雄提醒过之后的第二次 |

test：8 位玩家，48 个正例、67 个负例（另 23 个重复）。判分：正例要开口并含关键词之一；负例要不开口。

### 4.3 e2e_g1：游戏状态 + 聊天问答

10 位玩家（2 dev + 8 test），每人 13 段聊天和一次夸大段位的说法；游戏题（当前段位、赛季最高、英雄胜率 / 场次、最近常用英雄、主要位置、上赛季场数、最长连败）答案由对局计算；另有生活事实、承诺、"游戏事件 × 那天的聊天"和负例题。test 150 题。

## 5. 结果

### 5.1 游戏时刻的主动回忆（E21，e2e_g2 test）

| 记忆 | 主分 | 召回 | 该沉默时沉默 | 重复时沉默 | LLM 调用 |
|---|---|---|---|---|---|
| 无记忆 | 0.496 | 0.000 | 0.851 | 0.913 | 138 |
| Mem0（按时间顺序写入，按本局描述检索） | 0.339 | 0.000 | 0.582 | 0.609 | 138 |
| 检索（按本局描述取 8 段聊天） | 0.504 | 0.063 | 0.821 | 0.826 | 138 |
| 全部聊天 | 0.583 | 0.021 | 0.985 | 1.000 | 138 |
| 全部聊天，每句标注当时那局 | 0.539 | 0.042 | 0.896 | 0.783 | 138 |
| **GameMemory** | **0.861** | **0.667** | **1.000** | **1.000** | **47** |

GameMemory − Mem0 **+0.522 [+0.435, +0.617]**；− 检索 +0.357 [+0.270, +0.444]；− 全部聊天 +0.278 [+0.200, +0.357]；− 标注版全部聊天 +0.322 [+0.235, +0.409]。

**最强的长上下文对手**（预登记的子集：每位 test 玩家 1 个正例 + 1 个负例，16 个时刻）：把全部聊天和到这局为止的全部对局记录按时间交错放进 prompt（平均 1.1 万字），信息全在里面，召回 **0/8**、主分 0.438；同一批时刻上 GameMemory 召回 7/8、主分 0.938（+0.500 [+0.250, +0.750]）。

**意图索引本身**（不经过 LLM）：48 个正例命中 47 个；67 个负例上 0 次触发。唯一漏掉的是"上星耀我就把那盒马克笔买了"（意图词表认"就买"，没认"就把…买了"）。

**按意图类型的召回**（GameMemory / 最好的通用做法）：英雄教训 0.94 / 0.13，段位目标 0.75 / 0.00，双排约定 0.75 / 0.13，连输规矩 0.63 / 0.00，发誓不玩 0.00 / 0.13。

### 5.2 消融

| 变体 | 主分 | 召回 | 沉默 | 重复时沉默 | 说明 |
|---|---|---|---|---|---|
| GameMemory | 0.861 | 0.667 | 1.000 | 1.000 | |
| 线索交给模型决定说不说 | 0.739 | 0.375 | 1.000 | 1.000 | −0.122 [−0.191, −0.052] |
| 不限"第一次" | 0.817 | 0.688 | 0.910 | **0.000** | 每次都提醒；朋友目标误报 0.375 |
| prompt 里不标当时那局 | 0.896 | 0.750 | 1.000 | 1.000 | 差异不显著 |

- **决定"何时说"是记忆的职责**：同样的线索交给 3B 模型自己判断，召回从 0.667 降到 0.375。
- **"第一次"由对局流提供**：去掉之后，同一英雄的每一局都提醒（重复时沉默 1.000 → 0.000）；玩家自己的目标兑现之后，朋友的目标那一局又触发一次。
- **对齐的作用在索引里，而不在 prompt 文字里**：在 prompt 里写出"当时那局"对 3B 回复模型没有帮助（我们预登记的这一假设没有成立）。"这英雄"的解析发生在索引里，两个变体共用；它的作用体现在和通用做法的对比上——只说"这英雄"的意图，检索 / 全部聊天 / 标注版的召回是 0.067 / 0.000 / 0.000。

### 5.3 换更强的回复模型（7B，探索）

| 记忆 | 主分 | 召回 | 该沉默时沉默 | GameMemory 领先 |
|---|---|---|---|---|
| Mem0 | 0.548 | 0.000 | 0.940 | +0.383 [+0.296, +0.470] |
| 检索 | 0.522 | 0.104 | 0.821 | +0.409 [+0.322, +0.496] |
| 全部聊天 | 0.470 | 0.146 | 0.701 | +0.461 [+0.365, +0.557] |
| **GameMemory** | **0.930** | **0.833** | **1.000** | — |

换成 `qwen2.5:7b` 后，GameMemory 的召回从 0.667 升到 0.833，通用做法却没有变好：全部聊天开口更多，误报也多得多（沉默 0.985 → 0.701），Mem0 仍然 0 召回。**更强的回复模型补不上"在哪一局该想起哪句话"**，这一步属于记忆。"发誓不玩"一类在 7B 上仍是 1/8：模型提起了那局的失败，却刻意不复述玩家的誓言——索引取对了那句话，回复模型选择了委婉的说法。

## 6. 分析：通用记忆为什么做不到

**失败一：没有提问，就没有检索线索。** 检索式记忆只能拿"刚才这局"的描述去检索。"玩家刚用百里守约打完一局"和"这英雄我是真玩不明白，我发誓再也不碰了"在文字上几乎不相似，取回的是别的聊天，于是在错的时间说错的事（检索的沉默率 0.821，Mem0 0.582）。

**失败二：改写丢掉了意图。** Mem0 把聊天改写成事实时，"再也不碰这英雄"这类话或被丢弃，或被改错（dev 上这段对话在 Mem0 里只剩下一条与事实不符的"连输了四把、掉回钻石三"）。它的召回是 0。这与我们在 LoCoMo 上观察到的写入损失一致（E19）。

**失败三：信息都在，模型也不开口。** 把全部聊天交给模型，它几乎从不开口（召回 0.021、沉默 0.985）；给每句标上当时那局后，它开始开口，但说的多是不相关的事（重复时沉默 1.000 → 0.783）。决定"这一局该不该提哪件事"需要对照对局流做精确的条件判断（是不是这个英雄、是不是第一次、是不是升入了这个档位），这不是一个小模型能从长上下文里稳定读出来的。

**GameMemory 的做法**把这三件事从模型手里拿走：触发由对局流决定（失败一），原话不改写（失败二），条件由游戏规则和对局记录精确判断（失败三）。

## 7. 局限

- **回复这一步仍会丢分。** 意图索引命中 47 次，3B 模型最终说对 32 次（7B 40 次）；"发誓不玩"一类 0/8——线索命中了，模型却写"看来你对花木兰还有些心得"，不提玩家发过的誓。
- **意图抽取是规则。** 对局对齐和线索判断依赖游戏结构，是可靠的；"这句话是不是意图"用的是词表，换一种说法可能漏掉（test 上漏了 1/48）。
- **数据是模拟的。** 对局规则做了简化（每局 ±1 星、赛季重置统一降 12 星）；意图的种类和"点名 / 不点名"的比例由计划指定，作者只负责措辞。真实玩家的意图种类和说法分布需要真实数据检验。
- **任务一的高分部分来自题目设计。** 游戏数据题和档案卡的行几乎一一对应（只给档案卡就有 0.986）；有信息量的对比是和"拿到全部对局数据但当文本处理"的做法比。
- **最强的长上下文对手**（全部聊天 + 全部对局记录，平均 1.1 万字）在 CPU 上每个时刻约 9 分钟，只在 16 个时刻的子集上评测（结果见 §5.1）。

## 8. 相关工作

**LLM 智能体的长期记忆。** Mem0 [1] 在写入时抽取并合并事实；MemGPT [2] 让模型像操作系统一样管理分层记忆；Generative Agents [5] 用重要性、近因和相关性检索记忆流并做反思。它们的读取都由当前输入（提问或观察）驱动。我们此前在 LoCoMo [3] 上验证了改写式记忆在小模型上的写入损失（E19）。

**前瞻记忆。** 认知心理学区分基于时间和基于事件的前瞻记忆 [4]：后者由外部线索触发，通常比依赖主动回想更可靠。GameMemory 把对局流作为外部线索源，把这一区分落实到智能体记忆上。

**评测。** 现有记忆基准多为问答（LoCoMo [3] 等），只评测"被问时能否答对"。e2e_g2 评测"没被问时能否在对的时刻开口、在不该开口时沉默"。

---

## 9. 结论

游戏陪伴的记忆不只是"记得更多"，而是"在对的那一局想起来"。游戏数据提供了通用聊天场景没有的东西：一条客观、带时间、结构封闭的事件流。GameMemory 把它用作记忆的系统记录、对齐坐标和触发器，从而解决了查询驱动的通用记忆在结构上做不到的主动回忆问题。同样的设计适用于其他带结构化事件流的陪伴场景（运动、学习、健康记录）：事件流提供触发，聊天提供意图。
