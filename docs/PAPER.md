# Confidence-Based Updating of Shared Memory for Multi-Tenant Agents

# 多租户智能体共享记忆的置信度更新

GameMemo 项目技术报告 · 2026 年 10 月

代码 `gamememo/quorum.py`、`bench/commons_run.py` · 数据 `bench/data/commons1.json` · 完整实验记录 `docs/EXPERIMENTS.md`

## 摘要

当一个长期运行的智能体同时服务多个租户（例如为电商平台上的多家店铺提供客服）时，共享记忆需要同时满足两个相互冲突的目标：把在部分租户上获得的经验迁移到新租户，同时不让任何租户的具体信息或专属约定进入其他租户的上下文。我们将后者的失败区分为**实例泄露**（其他租户的姓名、订单、电话等具体信息出现）与**伪泛化**（只在特定租户、特定条件下成立的做法被推广到不满足条件的租户）。本文主张共享记忆应当**基于置信度更新**：共享层只保存结构化的候选做法及其在**不同租户**上的成功与失败证据，原始交互始终保留在租户私有层；每条新记录更新对应候选的证据与置信度，候选的适用范围由触发条件限定。我们给出两种实例化：硬阈值的 QUORUM（至少 k 个不同租户成功才进入共享层）与分级置信度检索（所有候选按置信度排序并附证据）。我们构建 COMMONS-1，一个由不接触被测代码的作者编写的中文多店铺客服基准，并在 3B 与 7B 两个本地模型上进行预登记实验。原始记录共享池使 7B 模型将一家训练店铺顾客的手机号告知其他店铺的新顾客（泄露率 0.063），且每次检索都向模型暴露其他店铺的实例信息（48/48）；经语言模型去隐私改写的经验共享池消除了实例暴露，但在 25% 的相关请求上把其他店铺的专属约定施加给新顾客。基于置信度更新的共享记忆在两个模型上均实现泄露、伪泛化与上下文暴露为零；硬阈值版本的代价是经验迁移下降（7B：0.375–0.583，原始记录池为 1.000），分级置信度版本的迁移效果为【待补】。

## 1 引言

### 1.1 问题

个人记忆只有一个主体：准确记住当前用户。共享记忆有两个可能冲突的主体：

1. **迁移**：把在先前租户上验证有效的做法用于新租户；
2. **隔离**：不把任何先前租户的具体实例或未经授权的特例带入新租户。

访问控制只能隐藏某一条记录，却无法阻止摘要模型把记录内容写入全局可读的摘要。因此隔离必须约束共享记忆的**写入路径**，而不仅是读取路径。

### 1.2 两类污染

**表 1** 共享记忆的两类污染

| 污染 | 定义 | 示例 |
|---|---|---|
| 实例泄露 | 其他租户的具体信息（名称、顾客姓名、订单号、电话、地址）出现在当前租户的上下文或回复中 | 向新顾客说"请保持电话 15081967273 畅通"，该号码属于另一家店铺的顾客 |
| 伪泛化 | 仅在特定租户、特定条件下成立的做法被施加于不满足条件的租户 | 把一家玻璃器皿店"破损补发并加赠防震收纳盒"的专属约定承诺给其他店铺的顾客 |

### 1.3 本文贡献

1. **原则**：共享记忆应基于置信度更新——共享层只保存结构化候选做法及其独立租户证据，每条记录更新置信度，适用范围由条件限定；原始交互不离开租户私有层。
2. **方法**：两种实例化，硬阈值的 QUORUM 与分级置信度检索。
3. **评测**：COMMONS 指标体系（经验增益、实例泄露、伪泛化，并补充上下文层面的暴露）与 COMMONS-1 数据集。
4. **发现**：(i) 共享记忆的风险首先存在于交给模型的上下文，回复层的泄露只是其在较强模型上的显现；(ii) 语言模型去隐私改写能够去除个人信息，但无法阻止伪泛化；(iii) 基于置信度的结构化共享在两个模型上均实现零污染，迁移代价取决于置信度的使用方式。

## 2 方法：基于置信度更新的共享记忆

### 2.1 两层存储

```
租户私有层                                   共享层
──────────────────────────────              ──────────────────────────────
原始交互（顾客消息、客服回复、结果）           结构化候选：问题类型 + 触发条件 + 做法
私有事实                                     每个候选的不同租户成功 / 失败证据（加盐令牌）
                               ── 只传结构化候选 ──►   置信度
```

原始交互与私有事实只写入租户私有层。共享层接收的每条候选只包含问题类型、触发条件标签与做法；候选在进入候选账本前经过安全策略检查（不得包含所声明的私有事实、租户标识或常见标识符模式）。

### 2.2 置信度更新

对候选 $c$，记 $S_c$、$F_c$ 为在其上成功与失败的**不同**租户数（同一租户重复记录只计一次，以加盐哈希令牌计数）。每条新记录到达时更新 $(S_c, F_c)$，并以 Wilson 单侧 95% 下界作为置信度：

$$\mathrm{conf}(c)=\frac{\hat p+\frac{z^2}{2n}-z\sqrt{\frac{\hat p(1-\hat p)}{n}+\frac{z^2}{4n^2}}}{1+\frac{z^2}{n}},\quad \hat p=\frac{S_c}{n},\ n=S_c+F_c,\ z=1.645$$

1、2、3 家租户成功且无失败时，置信度分别为 0.27、0.42、0.53；失败使置信度下降，候选可能因此退出共享层。

### 2.3 条件化适用范围

候选携带触发条件标签。检索时，仅当当前请求的条件标签包含候选的全部条件标签时，候选才可被返回。带有额外条件（如 `vip_member`）的店铺专属约定，在不满足该条件的租户上不可检索。

### 2.4 两种实例化

- **QUORUM（硬阈值）**：候选满足 $S_c \ge k$、成功率不低于阈值且失败数不超过上限时进入共享规则集；检索返回条件匹配的共享规则。
- **分级置信度（conf）**：不截断，返回条件匹配且 $S_c \ge 1$ 的全部候选，按置信度降序排列，并把证据（"2 家店铺独立验证有效、0 家无效；可信度 0.42"）一并交给回复模型。

## 3 实验设置

### 3.1 COMMONS-1 数据集

一个电商平台的客服智能体为多家店铺服务。由不接触被测代码的作者编写：8 个平台内部处理流程（每个含一个编造的操作名，如「资金回流核单」，模型无法凭常识猜得）、4 个店铺专属约定（如 VIP 会员退款由店铺余额先行垫付并赠送 30 元无门槛券），以及全部对话文本。12 家训练店铺按顺序产生 29 条处理记录：8 个流程分别有 5/4/3/3/2/2/1/1 家店铺成功处理过，另有 4 条以常见说法处理失败的记录与 4 条专属约定记录。8 家留出店铺（2 家开发、6 家测试）的顾客就这 8 类问题求助，测试集 48 条。顾客姓名、订单号、手机号、地址由带固定种子的计划生成，作为泄露检测的金丝雀。

### 3.2 比较的记忆

所有条件使用同一回复模型与同一提示；每条请求同时提供顾客消息与工单字段（问题类型、条件标签）。

**表 2** 比较的共享记忆

| 条件 | 共享层内容 | 检索 |
|---|---|---|
| 无记忆 | — | — |
| 原始记录池 | 所有店铺的原始处理记录 | 相似度 top-3 |
| 去隐私经验池 | 每条成功记录由语言模型改写为去除个人与店铺信息的经验 | 相似度 top-3 |
| QUORUM（k = 2, 3） | 至少 k 家不同店铺成功的结构化做法 | 条件匹配 |
| QUORUM + 示例 | 同上，并附一条以声明字段占位符脱敏的处理示例 | 条件匹配 |
| 分级置信度 | 全部结构化候选及其证据与置信度 | 条件匹配，按置信度排序 |

### 3.3 指标

- **经验增益**：回复中出现该流程的操作名；
- **实例泄露**：回复中出现任何训练店铺的金丝雀，或训练顾客的"姓 + 女士 / 先生 / 小姐"（与当前顾客同姓者除外）；
- **伪泛化**：回复中出现店铺专属约定的关键词（仅在存在对应约定的 4 类问题上统计，测试集 24 条）；
- **上下文暴露**（事后补充）：交给模型的记忆内容中出现其他店铺的实例信息或专属约定关键词。

全部为确定性判分；比较使用按条配对的 bootstrap 95% 置信区间。

### 3.4 协议

测试前登记假设（见 `docs/EXPERIMENTS.md`）。**封存更正**：该分支的 `.gitignore` 忽略了所有 JSON 文件，数据文件在测试运行后才进入仓库；由固定种子的计划与作者文本重新组装所得文件与运行时所用文件逐字节一致（sha256 `b12ed24f…f2a85c`），且其生成时间早于测试运行。分级置信度条件的设计提出于第一组测试结果之后，单独预登记。

## 5 分析

**风险首先在上下文。** 原始记录池在每一次检索中都把其他店铺的顾客信息交给模型（48/48），近一半检索同时带入其他店铺的专属约定（22/48）。3B 模型未在回复中照抄，7B 模型则把一位训练顾客的手机号写给了三家不同店铺的新顾客。以回复层泄露评估共享记忆，会随模型能力增强而突然失效。

**去隐私改写无法阻止伪泛化。** 改写模型不掌握"某一做法仅属于某一店铺的专属约定"这一信息，将"补发并加赠防震收纳盒""店铺余额先行垫付"写成通用经验；7B 回复模型在 6/24 条相关请求上照做。伪泛化是范围信息的丢失，而不是个人信息的残留，只有在写入时保留适用条件才能防止。

**结构化与置信度带来隔离。** 共享层只保存结构化候选、并以条件标签限定范围时，两类污染与上下文暴露在两个模型上均为零。硬阈值将只被 1–2 家店铺验证过的做法完全排除，这是迁移代价的主要来源之一；另一来源是规则形式的做法不如具体示例容易被模型复用（支持 ≥3 家的流程上，QUORUM 为 0.75，原始记录池为 1.00）。

**最有效的迁移形式最难安全共享。** 为规则附加以声明字段占位符脱敏的示例，在 3B 上把增益由 0.229 提高到 0.542（k=2），但示例中的"金女士"并非声明字段，未被替换，模型以此称呼另一家店铺的新顾客。基于字段替换的脱敏无法覆盖派生身份信息。

## 6 局限

1. COMMONS-1 中所有"仅一家店铺使用过"的做法均为真实的平台流程，不包含"某店铺自身的特殊做法却未标注额外条件"的情形；因此把低置信度候选交给模型的风险，本数据集无法检验。
2. 条件标签由工单系统给出，被假定为准确；真实系统中标签错误会直接导致伪泛化。
3. 候选做法以完全相同的文本表示同一做法（对应工单系统中的处理模板）；当不同租户以不同措辞描述同一做法时，需要先做做法归并。
4. 未覆盖投毒、合谋、女巫租户、删除权下的证据撤回，以及向量、日志、缓存等侧信道。
5. 数据为合成，规模较小（测试集 48 条），置信区间较宽。

---

## 7 结论

共享记忆的核心难题不在容量，而在共享内容的粒度与范围。在 COMMONS-1 上，原始记录共享与语言模型改写共享分别在实例泄露与伪泛化上失败，且失败随模型能力增强而显现；以独立租户证据为依据、以置信度更新、以条件限定范围的结构化共享记忆，在两个模型上均实现零污染。如何在保持零污染的前提下恢复示例级别的迁移效果，是后续工作的主要方向。
