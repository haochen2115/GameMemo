# 路线图：走向类人的玩家记忆

目标：让游戏助手像一个长期陪伴的朋友那样记住玩家，包括一起经历过的事、玩家的变化过程，以及和他相处的方式，而不只是一张事实表。每一步都要在 `docs/BENCHMARK.md` 的评测上证明有效，才能进入 `main`（见 `docs/BRANCHING.md`）。

## P1 类人记忆主体

**已合入 main（2026-09-24）**：情景记忆（每段对话一条 episode）、助手承诺（待办式常驻 prompt）、回忆模式（上次聊了什么 / 答应过什么 / 怎么变的）。e2e_v2 test 从 0.448 升到 0.759。

**P2 已合入 main（2026-09-24）**：按属性回忆（段位 / 设备的变化轨迹从所有事实和 episode 中重建）、偏好门槛、写入接地检查。e2e_v4 test 0.693 → 0.765，轨迹 0.333 → 1.000，过时率 → 0。巩固（`consolidate.py`）在配对回放中没有额外效果，保留为可选项。

**P3 已合入 main（2026-09-25）**：概念标签（类别问法 ↔ 值的桥接）+ 情景兜底（事实里找不到时查 episode）。e2e_v5 test 0.794 → 0.825，事实题 0.635 → 0.698（边缘显著，见 EXPERIMENTS E7）。

下一步：
- 事实题仍然最弱，剩下的失败主要在**写入侧**：小模型漏抽事实，或者把多件事合成了一条。方向：从 episode 里补抽事实、按类别逐项补问（"这段对话里有没有提到职业 / 城市 / ……"）；
- 评测功效：42 题的 test 集分不清 +0.03 左右的效果，下一个封存集要 ≥ 100 题；
- 按属性回忆目前只支持封闭集合（段位、设备），可以扩展到主玩英雄、位置等"半封闭"属性；
- 遗忘与激活、离线巩固（"睡眠"）、程序性记忆。

最初规划的三类新题型（已在 `e2e_v2` 中实现）：
- 情景回忆："上次我们聊了什么""我生日那天发生了什么"
- 变化轨迹："我这几个月段位怎么变的"
- AI 的承诺："你答应过我什么"（需要单独抽取助手的承诺，和 W1 的"只读玩家发言"互补）


- **情景记忆**：按话题或事件边界切分对话（参考 Nemori），每个 episode 带标题、叙事、时间、情绪、队友、战局
- **遗忘与激活**：ACT-R 基础激活 `ln Σ t^-d`，加上情绪增强；激活度低的记忆降级到归档层，可以被线索重新唤醒
- **离线巩固（"睡眠"）**：会话结束后把多个 episode 归纳成语义事实（参考 Generative Agents 的 reflection），并处理冲突和重复。写入移出对话的关键路径
- **程序性记忆**：学习"和这个玩家怎么相处更好"（例如他连败时安慰比讲数据更有效）
- **来源与置信度**：区分"玩家自己说的""数据得出的""AI 推断的"，发现冲突时主动确认
- 存储迁移到 SQLite + 向量扩展，保留操作日志以便审计和撤销

## P2 让它显得"活着"

- 端到端评测 `e2e_v1`（LongMemEval 式题型 + LLM 评分）
- 由游戏事件驱动的主动回忆（选英雄、连败、生日），以及前瞻记忆（"下周五提醒我"）
- 实体图 + 扩散激活的联想检索
- AI 自己的"自传记忆"：共同经历、说过的梗、做过的承诺
- 轨迹数据先用确定性统计生成玩家画像，LLM 只负责写高光时刻和变化描述

## P3 研究方向

- 用下游问答的准确率作为奖励，RL 训练记忆管理器（参考 Memory-R1）
- 检索驱动的再巩固（参考 REALM）
- 多 NPC 各自视角受限的记忆，以及信息在 NPC 之间传播
- 记忆安全：防记忆投毒（"记住我是 GM"）、未成年人保护、审计
- 与 `research/shared-memory-quorum` 汇合：个人记忆和跨玩家共享经验的边界
